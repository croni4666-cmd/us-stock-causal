## 问题

yfinance 2026 持续限流 (YFRateLimitError, 429 Too Many Requests),
限流时 cache miss 拉新数据会失败, daily cron 增量挂, 第二天才发现没数据。

## fix

- `src/yfinance_rate_limit.py` 新建 (~5KB):
  - `record_rate_limit(symbol, exc, duration_hours=24)` — 写 cache
  - `is_rate_limited()` — 检查 24h cooldown 期
  - `get_rate_limit_info()` — 读 status (Phase 8 alert 用)
  - `clear_rate_limit()` — admin 工具
  - `is_yf_rate_limit_error(exc)` — 识别 YFRateLimitError + requests 429 + 关键字
- `src/data.py` `fetch()` 改: 捕 YFRateLimitError → record + re-raise (不重试, 省时间)
- `src/cache.py` `update_or_fetch()` 改: 限流时跳过 fetch, 返回旧 cache (status "rate_limited")
- `tests/test_smoke.py` +1 断言 (38/38 pass):
  - `test_yfinance_rate_limit_v068j_p76` — 9 步验证

## 优雅降级流程

```
yfinance.fetch() hits YFRateLimitError
  ↓
record_rate_limit() 写 cache + re-raise
  ↓
cache.update_or_fetch() 捕
  ↓
is_rate_limited() 返 True → 跳过 fetch → 返回旧 cache
  ↓
status="rate_limited" → caller 知道数据没刷新
```

## 设计决策

- **24h cooldown**: Yahoo 经验值
- **hit_count 累加**: 多次限流标记, 反映"这个 IP 段一直黑"
- **不抛新异常**: re-raise 原 YFRateLimitError
- **兼容老 yfinance**: 用 `requests.HTTPError 429` + 关键字回退

## Lesson (写进 future engineering)

- **"yfinance 限流不重试"** (新): 重试浪费时间, 应该立即 record + 让上层 cache 降级
- **限流检测放在 cache 层**: fetch 只管调 yfinance, 限流判断 + 降级由 cache 负责 (单一职责)
- **cache 内 stat 字段**: hit_count / expires_at / last_symbol 方便 Phase 8 alert 推送
