# 数据积累与逐日核算

## 从采集到报告

在已安装项目依赖的环境运行：

```powershell
python -m examples.asset_report collect --start 2026-09-24 --end 2026-10-03 --with-constituents
python -m examples.asset_report inventory
python -m examples.asset_report report --start 2026-09-25 --end 2026-10-02 --mode retrospective --market-store data/asset_market --json-output output/asset_report.json
```

collect 的 end 不包含：查询到10月2日用10月3日。report 的两个端点均必须有实际观察。
默认采集 QQQ/IEF/TLT/GLD 官方输入和十一种资产报价；with-constituents 增加
本次 QQQ 官方名单中的股票。此名单是当前基金结构，不是历史无幸存偏差的指数样本。
命令逐项下载；部分失败返回非零，已成功的数据及失败清单保留在 data/asset_runs。
此流程不创建定时任务。以后每个交易日收盘后可重复运行 collect；每次取得的版本都保留。

inventory 完全离线。它分别列出所属日期、实际行情日期与取得时间。同一天下载两次，
有两个版本，但仍只有一天的持仓历史。缺日期不会补成相邻日，也不会生成假历史文件。
官方端点只提供最新持仓时，过去缺失的每日权重仍须通过经过核实的历史来源获得。

## 快照与时间

data/asset_market 保存提供商标准化日线与单独 JSON 元数据：查询区间、实际行数/日期、
字段、SHA256、UTC 取得时间。保留分红、拆股等可用字段；缺少字段保持缺失。
使用市场交易日收盘门槛拒绝仍未收盘的当日日线；GC=F采用纽约17:00保守门槛。
这些门槛不证明供应商的最终修订版本已发布。

指定 market-store 后，报告只读新快照，不从旧缓存补缺。旧 market-root/market-file
接口继续可用；不能同时指定新快照与 market-file。
事后模式选择覆盖精确端点的最新取得版本。point_in_time 限制行情快照在报告结束日
纽约16:30之前已取得；官方持仓仍遵守第一阶段期初时间规则。
因此现在下载旧价格不会被认证为当时可见行情。整个报告的历史可交易回测状态仍为 false。

## 公司行动

事件窗口为 (start, end]，起点当天事件已包含在起点价格状态中，不再计入窗口。
报告列明每股分红、资本利得及拆股比率。Yahoo close 已经按提供商口径处理拆股，
不再乘拆股比率；复权收益与价格收益之差不等于精确现金收益。
缺字段/空值不补零；每股金额未经历史股份口径验证，不能据此认证官方基金总收益。
缺少中间交易日时，事件观察日期列入缺口，整个窗口的现金合计保持未知，不能显示为零。

## QQQ 每日归因

第一阶段的固定期初权重近似继续显示。第二阶段另外要求每个交易区间都有与起点
同一天的真实基金权重，并检查所有 Nasdaq 交易日行情。不能跨过缺失交易日或
缺失权重日，也不会把当前名单作为 Nasdaq100/^NDX/^IXIC 的官方指数权重。
成分股价格只要求其实际被持有区间的精确端点；中途新增股票不用满足整段起点。
严格模式仍统一遵守报告结束日的行情快照取得时间门槛。

股票贡献用原始权重乘当日价格回报；缺失股票与现金、衍生品、分红等留在残差，
不重归一化。多日贡献用前一日实际 ETF 财富系数链接，链接贡献和残差合计等于
期间 ETF 价格回报。缺任何一天权重，不给完整期间链接贡献；部分有效区间只作
覆盖记录。JSON 保留逐日来源、股票输入哈希和权重日期供审查。

这是机械核算。真正因果研究仍需要时间戳明确的政策意外、高频报价、并发事件排除、
信息效应处理和样本外检验。
